Why is FiniBench Different?

Quantization & Agent Loops

KL Divergence Fails to Predict Agentic Performance

Model cards are usually advertised at FP16 quality, but most home labs run models at FP8 or even FP4 quality. Quantization levels that show minor quality loss on single-turn tests often suffer total task failure when subjected to multi-step tool calls.

Key Insight: A Q2 quant should be treated as a separate model from its FP16 equivalent.
Harness Impact

Harness Architecture Significantly Impacts Success

The design of an agent harness—including its prompt structures, tool definitions, and edit formats—exerts a major influence on task completion rates. Benchmark suites must evaluate models across standardized harnesses to isolate weight precision effects from harness overhead.

Key Insight: LLMs don't work alone, the harness matters even more.
Task Efficiency

Token Efficiency and Reasoning Length Confound Results

Evaluating agentic workflows requires shifting from raw generation speed (tokens per second) to outcome-oriented metrics: Task Speed (tasks/hr) and Intelligence Density (tasks/GB). These metrics provide an objective measure of system utility on fixed hardware footprints.

Key Insight: Outcome efficiency measures real work delivered per unit of resources.

Our Methodology

🖥️ Model Serving

Our model serving infrastructure evaluates open-weight AI models across the two most popular local inference runtimes llama.cpp and vLLM. All models are served on an Nvidia DGX Spark with 128GB of VRAM.

  • Weight Precision & Quantization: We test FP16 unquantized baselines alongside FP8, INT4, NVFP4, and GGUF / EXL2 K-quants (Q8_0, Q6_K, Q4_K_M, Q3_K_M, Q2_K, IQ2_XXS).
  • Context & Memory Allocation: Context windows are configured to model max with optional KV-cache quantization enabled.
  • Sampling & Reproducibility: Temperature is set using the model-recommended value, but each test is run 3 times and the results averaged.
⚙️ Harness Setup

The agent harness environment orchestrates multi-turn tool loops, terminal execution, file system modifications, and error feedback recovery. We evaluate models across major open and commercial agent frameworks (OpenCode, Claude Code, Aider, Cline, AutoGen, CrewAI).

  • Edit Format Standardization: Evaluates performance across Unified Diff (line-level edits), Search & Replace blocks, AST Tree Mutations, and Full File Overwrites.
  • Tool & LSP Integration: System prompts specify explicit JSON schema tool calls with Language Server Protocol (LSP) feedback for instant syntax error diagnostics.
  • Loop Limits: Agents are permitted up to 30 sequential turns per problem instance before flagging a timeout or unrecoverable loop failure.
📊 Tests and Evaluation

FiniBench benchmarks end-to-end task completion on curated test suites including SWE-bench Lite, LiveCodeBench, GAIA, TAU-bench, HumanEval Multi-Turn, and MBPP. Rather than relying on single-turn token accuracy, we measure outcome-oriented engineering efficiency.

  • Tasks Solved / Hour (Tasks/hr): Quantifies total verified multi-turn tasks completed per 60 minutes of wall-clock execution time.
  • Tasks Solved / GB Memory (Tasks/GB): Measures hardware efficiency by normalizing task throughput against total run memory consumption.
  • Trace Logging: Every evaluation run generates a deterministic execution trace containing input/output token counts, run memory footprint, context utilization, and complete terminal logs.
